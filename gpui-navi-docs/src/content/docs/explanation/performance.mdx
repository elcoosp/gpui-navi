Navi's router is engineered for allocation-free hot paths. This page explains where the guarantees come from and what they bought, with the numbers from the repository's own benchmarks (`docs/BENCHMARKS.md`, criterion medians, 130-route tree).

## The guarantees

| Guarantee | Where you see it |
| :--- | :--- |
| **Zero-copy route matching** | Stack-collected parameter bindings, interned `Arc<str>` segment names, FxHash static-child lookup, `HashMap` materialized once on success. Matching is 14–38% faster across the board. |
| **Per-frame paths allocate nothing** | `use_params!`, `use_search!`, and `use_loader_data!` read navigation-time caches; `Link` active checks are branch-and-byte comparisons (−94%); loader `QueryKey`s are memoized per navigation. |
| **Bounded memory everywhere** | Ring-buffered event log, capped preload registry, O(1) scroll-eviction, `Arc<RouteTree>` shared between core and adapter (no deep tree clone at startup). |
| **Lock-free single-owner history** | No `Mutex` in the navigation path; back/forward is −67%. |

## Quality gates that keep it honest

The workspace enforces the same discipline in CI:

- `cargo clippy --workspace --all-targets -- -W clippy::pedantic -D warnings` — zero warnings, with no `#[allow]` attributes in the codebase (suppressions use targeted `#[expect]`, which errors when stale).
- The four validation integrations (`validator`, `garde`, `validify`, `valico`) are mutually exclusive blanket impls, so they are linted and tested **per feature** instead of under `--all-features`.
- `clippy.toml` calibrates a few shape thresholds for the devtools UI module's large render methods instead of scattering allow attributes.
- Criterion benchmarks (`benches/core.rs` for the engine, `benches/adapter.rs` for the runtime) guard the hot paths against regressions.

The rendering stack is quoin and the data stack is rs-query — both chosen so the router itself never blocks on a framework or an ambient async runtime.
