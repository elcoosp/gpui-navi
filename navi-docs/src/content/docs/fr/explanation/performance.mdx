Le routeur de Navi est conçu pour des chemins chauds sans allocation. Cette page explique d'où viennent les garanties et ce qu'elles ont apporté, avec les chiffres des propres benchmarks du dépôt (`docs/BENCHMARKS.md`, médianes criterion, arbre de 130 routes).

## Les garanties

| Garantie | Où vous la voyez |
| :--- | :--- |
| **Appariement de routes sans copie** | Liaisons de paramètres collectées sur la pile, noms de segments `Arc<str>` internés, recherche d'enfants statiques par FxHash, `HashMap` matérialisée une seule fois en cas de succès. L'appariement est 14 à 38 % plus rapide dans l'ensemble. |
| **Les chemins par frame n'allouent rien** | `use_params!`, `use_search!` et `use_loader_data!` lisent des caches du moment de la navigation ; les vérifications d'état actif de `Link` sont des comparaisons branche-et-octet (−94 %) ; les `QueryKey` de loaders sont mémoïsées par navigation. |
| **Mémoire bornée partout** | Journal d'événements en tampon circulaire, registre de préchargement plafonné, éviction de défilement en O(1), `Arc<RouteTree>` partagé entre cœur et adaptateur (pas de clone profond de l'arbre au démarrage). |
| **Historique sans verrou à propriétaire unique** | Aucun `Mutex` dans le chemin de navigation ; le retour/avance est −67 %. |

## Portes qualité qui gardent l'honnêteté

L'espace de travail impose la même discipline en CI :

- `cargo clippy --workspace --all-targets -- -W clippy::pedantic -D warnings` — zéro avertissement, sans attribut `#[allow]` dans la base de code (les suppressions utilisent `#[expect]` ciblé, qui échoue lorsqu'il est obsolète).
- Les quatre intégrations de validation (`validator`, `garde`, `validify`, `valico`) sont des implémentations globales mutuellement exclusives, donc elles sont lintées et testées **par fonctionnalité** au lieu de sous `--all-features`.
- `clippy.toml` calibre quelques seuils de forme pour les grandes méthodes de rendu du module UI des devtools plutôt que de disperser des attributs allow.
- Les benchmarks Criterion (`benches/core.rs` pour le moteur, `benches/adapter.rs` pour le runtime) protègent les chemins chauds contre les régressions.

La pile de rendu est quoin et la pile de données est rs-query — les deux choisis pour que le routeur lui-même ne bloque jamais sur un framework ou un runtime asynchrone ambiant.
