You inspect your router at runtime with the built-in devtools panel. It runs in-app on every supported framework — the panel itself renders through quoin, so GPUI, Dioxus, Leptos, Xilem, and Floem all get the same interface.

## Open the panel

Press the devtools keybinding:

| Platform | Shortcut |
| :--- | :--- |
| macOS | `Cmd+Shift+D` |
| Windows / Linux | `Ctrl+Shift+D` |

The keybinding is exposed through `DevtoolsModel::keybindings()`, so a host can also wire it into its own keymap.

## The four tabs

| Tab | What you do there |
| :--- | :--- |
| **Routes** | See the route tree visually and trigger test navigation. |
| **Cache** | Inspect and invalidate the rs-query loader cache. |
| **Timeline** | Read the event log with search, filter, and export capabilities. |
| **State** | Review router state, active navigation blockers, and metadata. |

## Read the timeline

The timeline records the navigation lifecycle as events. Each `DevtoolsEvent` carries a badge and badge color (`badge()`, `badge_color()`) plus a description, and `LoggedEvent` formats the time for display. The router-side `RouterEventType` enumerates the six lifecycle stages the panel filters on:

`BeforeNavigate`, `BeforeLoad`, `Load`, `BeforeRouteMount`, `Resolved`, `Rendered`

Use the timeline to answer questions like "did my `before_load` guard redirect?" or "how long did the loader take?" — the `BeforeNavigate → BeforeLoad → Resolved` sequence tells the whole story of one navigation.

<Aside type="note">
  The devtools model is framework-agnostic (`navi-devtools`), built on the
  `DevtoolsModel` struct with a `render` seam that the host framework
  materializes. Timeline search is also settable programmatically through
  `tour_set_timeline_search` — handy for tests.
</Aside>
